# OrbitPOS 2.1.0-alpha.56

## Emisión y activación segura de licencias

- `license-generator generate` ahora exige una clave privada Ed25519 para emitir ORB3 por defecto.
- ORB2 se conserva únicamente con `--legacy-orb2` para migraciones controladas; no es el formato de emisión normal.
- El backend rechaza licencias vencidas o todavía no vigentes antes de guardarlas.
- Después de completar el asistente, `/api/license/activate` requiere una sesión autenticada de administrador.
- El QA comercial activa una licencia ORB3 real, comprueba el rechazo anónimo y verifica el rechazo de una licencia vencida.
- Los campos de licencia del asistente y del panel muestran ORB3 como formato esperado.

## Verificación

- `npm run qa:license` pasó generación ORB3, compatibilidad ORB2 explícita, huellas, claves incompatibles, archivos protegidos y validación de entradas.
- `npm run qa:commercial:node22` pasó activación ORB3, autenticación y expiración.
- El instalador incluirá la EULA y se volverá a generar con esta versión.
- La firma Authenticode, las pruebas físicas de dispositivos, la instalación limpia y la actualización real siguen siendo gates externos para producción estable.
