# OrbitPOS 2.1.0-alpha.54

## Autorización efectiva en la API

- Se agregó middleware de permisos por módulo y acción en el backend.
- Los módulos de Ventas, Productos, Compras, Proveedores, Clientes, Créditos, Caja, Devoluciones, Reportes, Notificaciones, Ayuda y Cotizaciones validan el permiso efectivo de la sesión.
- Productos conserva el acceso de lectura desde POS para que un cajero pueda vender, pero las mutaciones siguen protegidas para administradores.
- El QA comercial comprueba que un cajero pueda consultar el catálogo, pero reciba `403 PERMISSION_DENIED` al intentar consultar Reportes o Compras sin esos permisos.

## Verificación

- `npm run qa:commercial:node22` pasó con validaciones de autorización directa contra la API.
- Se conserva la inclusión de `docs/EULA.txt` en el instalador mediante NSIS.
- La firma Authenticode, las pruebas físicas de dispositivos, la instalación limpia y la actualización real siguen siendo gates externos para producción estable.
